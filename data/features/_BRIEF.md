# Feature page content brief (for the writing agents)

Each feature page on allcoaching.in (`/features/<slug>`) is generated by `.claude/scripts/build_feature_pages.py` from one JSON file here: `data/features/<slug>.json`. You write the JSON and export the screenshots it uses. You do not write HTML.

## Sources (read them, do not invent)
- **What the feature really does:** the tutorial voice script `C:\Users\allco\codes\video-studio\scripts\make-<feat>-script.py` (use the English beats; if a `-v3` version exists for that feature, it is the newer one). It describes exactly what the studio screen shows.
- **Title and FAQ tone:** the YouTube SEO entry for the feature in `video-studio/scripts/seo.py` and the FAQ answers in `video-studio/scripts/seo_faq.py`.
- **Facts and banned claims (binding):** `CLAUDE.md` (repo root), `.claude/skills/allcoaching/references/01-product-and-studio.md`, `02-pricing.md`, `04-voice-and-claims.md`.
- **Screenshots:** real 4K studio shots in `C:\Users\allco\codes\video-studio\public\shots\*.png` (3840x2160; each has a `.json` of element boxes in 1920x1080 CSS px). Demo academy website shots in `public/shots/site/`. Look at a shot before you use it.

## JSON schema (all strings plain text, no HTML; use ’ for apostrophes or plain ')
```json
{
  "slug": "test-series",
  "nav": "Test series",
  "group": "teach",
  "eps": ["05"],
  "title": "Online Test Series with Rank and Percentile | AllCoaching",
  "description": "50–160 characters, answer-first, what the educator can do.",
  "keywords": "online test series platform, mock test app for coaching, ...",
  "eyebrow": "Test series",
  "h1": ["Light setup line,", "bold payoff."],
  "lede": "2–3 sentences, educator-first, concrete.",
  "notes": ["short tick 1", "short tick 2", "short tick 3"],
  "card": "One line (≤ 90 chars) used on the features hub and related cards.",
  "sections": [
    {"eyebrow": "Build", "h2": ["Setup words.", "Payoff words."], "body": "2–3 sentences.",
     "bullets": ["3–4 concrete bullets"], "img": "/assets/x/f/test-series-1.webp",
     "alt": "Describe the screen", "phone": ""}
  ],
  "steps": [{"t": "Step title", "d": "One sentence."}],
  "faq": [{"q": "Question?", "a": "Answer in 1–3 sentences."}]
}
```
- `group`: one of `build`, `teach`, `sell`, `run`.
- `eps`: first episode is the hero video; add a second only for `courses` (02, 03).
- `title` ≤ 65 characters including " | AllCoaching". `description` 50–160 characters.
- `sections`: exactly 3. Each must have a real screenshot `img` you exported. `phone` is optional: a phone-shaped screenshot path (existing: `/assets/x/m-home.webp`, `/assets/x/m-courses.webp`, `/assets/x/m-course.webp`) for at most one section per page where a student view helps.
- `steps`: 3–5, taken from the tutorial flow.
- `faq`: 4–5. Real questions an educator asks (use `seo_faq.py`). The answer text is used verbatim in visible HTML and in FAQPage JSON-LD.

## Screenshot export
For each section image, crop the relevant area of a 4K shot (crop box in 3840x2160 px; keep a 16:9 or 16:10 ratio, at least 1600 px wide before resizing), resize to 1600 px wide, and save as WebP quality 80 to `C:\Users\allco\codes\allcoaching-prod-landing\assets\x\f\<slug>-<n>.webp` (n = 1,2,3). Use PIL. Look at every exported file.
- Avoid shots that show personal names ("kaya", "AJANTA…", "Amit" as an account), real phone numbers or emails, red "Failed" rows, exclamation marks in thumbnails, or "14 days free". Demo data ("Demo Academy", "Demo Course", "Student A") is fine.
- Prefer a crop that shows the feature clearly over the whole screen with the sidebar.

## Writing rules
- Voice: calm, confident, editorial. Say "educator", "studio", "your students". No exclamation marks. No "unlock", "maximize", "creator".
- Never claim: free plan, free forever, ₹0, "#1", cheapest, 14-day trial, AI question or test generation, a live or free demo, guaranteed students or income, sales limits, payout speed other than "Razorpay settlement, usually T+2 days, instant settlement available", fabricated numbers.
- Trial is 7 days, no card needed. "0% commission / keep 100%" is monthly plans only. iOS app is Growth and Pro, after 30 days; never Starter. Apps are published on the educator's own Play Console / App Store Connect. DRM and watermarking are on every plan (do not name DRM standards).
- Only describe what the tutorial script or the screenshots show. If unsure, leave it out.
- Do not mention or show Biology Lessons, CHEMPSI or DigiteKM.

- Edit any HTML, CSS or JS file, or anything outside `data/features/` and `assets/x/f/`.
- Run git commands that change state (no commit, push, stash, checkout, reset).
