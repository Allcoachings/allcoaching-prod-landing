How one small change ships

A new control touches three repos. Follow this order every time, so the studio, the server and the website always agree.

Step 1 · renderer repo
Add the field

In themes/classic/registry.json (allcoaching-student-web). Give it a default that keeps today's look.

Step 2 · renderer repo
Generate the schema

npm run themes:schema writes the field into allcoachingAdmin. Never edit the generated files by hand.

Step 3 · renderer repo
Draw it

Use the setting in apps/learn/src/classic/sections and style it in classic.css.

Step 4 · both repos
Check, then push

Type check, themes:check, sections:check. Push both. Django deploys to Hostinger by itself.

Step 5 · Vercel
Sumit deploys

The renderer goes live only with vercel deploy --prod. The studio shows the new field as soon as Django is live.

An empty setting keeps the old lookA new switch is read as "on" when it is missing, so academies that never touched it see no change.
The studio needs no code for most controlsText, toggles, sliders, images, icons, dates and course pickers already show up in the right panel from the schema.
One control, one jobA switch says what it does ("Show images"), and the help line says what happens when it is off.
Samples never go liveAn empty section shows sample content in the editor only, never on the educator's website.
